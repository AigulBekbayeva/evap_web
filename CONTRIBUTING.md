# Участие в проекте

## Перед пул-реквестом

```bash
pytest tests/ -v
cd web && node test.mjs
PYTHONPATH=src python scripts/check_js_port.py
```

Все три должны пройти. Третья проверка обязательна, если трогали физику: она
сверяет `web/js/physics.js` с `src/evap/physics.py` на одинаковых входах.

## Правка формул

Физика продублирована на Python и JavaScript. Меняете в одном месте — меняйте в
обоих, иначе `check_js_port.py` упадёт.

Правьте формулу — добавьте тест. История проекта показывает, почему: две
ошибки (коэффициент Брунта и Пенман внутри теплового баланса) давали
правдоподобные на вид числа и прошли бы любую проверку «результат конечен и в
разумных пределах». Поймали их только проверки **амплитуды** годового хода
температуры воды и **знака** влияния глубины.

Полезные виды тестов:
- сравнение с опорными значениями из FAO-56;
- аналитические предельные случаи (штиль, насыщенный воздух, ночь);
- физическая согласованность (замыкание годового цикла теплозапаса);
- знак отклика на изменение параметра, а не только величина.

## Стиль

Python: PEP 8, аннотации типов в сигнатурах, докстроки на русском.
JavaScript: ES-модули, без сборщика — код исполняется браузером как есть.

Комментарии объясняют **почему**, а не что. «Здесь массоперенос, а не Пенман,
потому что...» полезно; «вызываем массоперенос» — нет.

## Проверка на реальных данных

Синтетика ловит грубые ошибки, но не всё. Если правите расчёт, прогоните на
реальном водоёме и сравните годовые суммы до и после. Расхождение больше
нескольких процентов без объяснения — повод остановиться.

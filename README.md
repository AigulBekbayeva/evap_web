# sorbulak-evap

Расчёт испарения с поверхности озёр и водохранилищ методом Пенмана.

Два способа использования: **браузерное приложение** — обвести контур на карте и
сразу получить результат, и **Python-пакет** — для случаев, когда нужна
спутниковая температура воды и калибровка.

## Зачем

Для бессточного водоёма в засушливом климате испарение — главная расходная
статья баланса. Оно определяет уровень, а уровень определяет площадь мелководий,
нагрузку на дамбы и площадь обнажённого засоленного дна.

Готовые спутниковые продукты испарения над водой при этом не работают:

| Продукт | Почему не подходит |
|---|---|
| MOD16A2 | Водные пиксели исключены из расчёта — там NoData |
| PML_V2 | Над водой сводится к Пристли–Тейлору без теплозапаса; в сухом климате занижает |
| GLEAM | Разрешение 0.25° (~25 км), сигнал озера растворён в сухопутной ячейке |
| SEBAL / METRIC / SEBS | Требуют опорных пикселей на суше; над водой физика другая |
| ERA5 `potential_evaporation` | Эталонная трава, альбедо 0.23 — занижение на 20–35 % |

Все они рассчитаны на растительность.

## Браузерная версия

Ничего устанавливать не нужно. Открываете страницу, обводите акваторию по
спутниковой подложке, задаёте среднюю глубину и период — расчёт идёт целиком в
браузере, данные никуда не отправляются.

**Что получаете:** матрицу испарения год × месяц, средний годовой ход, межгодовую
динамику с оценкой значимости тренда, объём потерь в млн м³, выгрузку в CSV.

**Как берётся температура воды.** Спутниковая термометрия из статической
страницы недоступна, поэтому Tw моделируется: интегрируется тепловой баланс
водной толщи с заданной вами глубиной. Это принципиально лучше, чем приравнять
температуру воды к температуре воздуха — воспроизводится тепловая инерция, и
теплозапас работает физически осмысленно.

> **Проверить результат нечем.** Глубина остаётся свободным параметром,
> наземных измерений нет. Сравнивать годы и месяцы между собой можно смело:
> систематическая ошибка одинакова для всех. К абсолютным значениям относитесь
> как к оценке порядка величины.

## Python-версия

Нужна, когда важна точность. Отличие одно, но существенное: **температура воды
берётся со спутника**, а не моделируется, и это позволяет восстановить глубину
из данных вместо того, чтобы задавать её на глаз.

```bash
git clone https://github.com/USER/sorbulak-evap
cd sorbulak-evap
pip install -e ".[geo,dev]"

# положить контур озера в data/shapes/
evap inspect                       # проверить геометрию

# выгрузить температуру воды: gee/export_data.js в code.earthengine.google.com
# → Tasks → скачать CSV из Drive в data/raw/
evap status                        # что уже скачано

evap run                           # расчёт
python scripts/calibrate_depth.py  # восстановить глубину
evap run --depth <найденная>
evap map --serve                   # интерактивная карта
```

Earth Engine из Python не вызывается: он нужен один раз, через веб-редактор,
чтобы выгрузить температуру воды. Метеорология идёт через Open-Meteo.

> **Почему не Python API Earth Engine.** `getInfo()` считает граф синхронно и
> упирается в лимит памяти («User memory limit exceeded») уже на нескольких
> годах. `Export.table.toDrive` ставит задачу в очередь на серверах Google, где
> лимиты на порядки выше. Это разница в архитектуре, а не в объёме данных.

## Метод

```
       Δ (Rn − G) + γ · f(u) · (es − ea)
E =  ─────────────────────────────────────
              λ (Δ + γ)
```

Первое слагаемое — радиационная составляющая, второе — адвективная. В сухом
климате адвективная часть велика, поэтому подходы на основе Пристли–Тейлора
здесь занижают результат.

**Теплозапас обязателен.** При глубине порядка 10 м водоём запаздывает за
атмосферой на недели. Игнорирование `G = ρw·cw·h·dTw/dt` даёт ошибку до 40 % в
отдельные месяцы: весной завышение, осенью занижение. На годовой сумме почти
замыкается, но помесячная динамика без него неверна принципиально.

Считаются три метода: Пенман (основной), массоперенос (независимый контроль) и
Пристли–Тейлор (диагностика адвективного вклада).

### Две ловушки, на которых легко ошибиться

Обе давали правдоподобные на вид числа и были найдены только численной
проверкой — теперь закреплены тестами.

**Формула Брунта.** Излучательная способность неба:
`ε_clear = 0.605 + 0.048·√(ea в гПа)`. Рядом в литературе ходит выражение
`(0.34 − 0.14·√ea)`, но это коэффициент для **чистого** длинноволнового баланса
(FAO-56, ур. 39). Подстановка его вместо ε занижает Rl↓ примерно на треть,
радиационный баланс уходит в минус, и температура воды схлопывается к нулю.

**Пенман внутри модели теплового баланса.** Пенман берёт дефицит влажности через
`es(Ta)` и почти не реагирует на температуру воды. Внутри модели баланса это
даёт положительную обратную связь: холодная вода слабее излучает вверх → Rn
растёт → испарение растёт → вода остывает ещё сильнее. Внутри баланса нужен
массоперенос с `es(Tw)` — тогда холодная вода испаряет мало и система замыкается
на равновесной температуре.

## Валидация без наземных данных

Проб нет, поэтому проверка строится на внутренней согласованности:

1. **Два метода с независимыми источниками ошибок.** Массоперенос калибруется по
   годовой сумме Пенмана, поэтому годовые итоги совпадают по построению.
   Информативно расхождение **по месяцам**: весной Пенман выше — завышен
   теплозапас, летом ниже — занижена радиация или завышено альбедо.
2. **Замыкание годового цикла теплозапаса.** За полный год `ΣG` должна быть
   близка к нулю.
3. **Сверка Landsat ↔ MODIS** (Python-версия). RMSE до 1.5 K — хорошо, до
   2.5 K — приемлемо.
4. **Воспроизведение известных закономерностей.** Испарение растёт с ветром,
   максимум в июне–августе, температура воды отстаёт от воздуха на 10–40 суток,
   более глубокий водоём сдвигает пик на осень.

| Величина | Ожидаемая ошибка |
|---|---|
| Суточное испарение | 15–25 % |
| Месячная сумма | 10–15 % |
| Годовая сумма | 8–12 % |

Для браузерной версии добавьте неопределённость глубины: она сильно влияет на
сезонный ход и слабо — на годовую сумму.

## Восстановление глубины

`scripts/calibrate_depth.py` не требует знать глубину заранее — он её
**восстанавливает**. Модель теплового баланса с заданной глубиной даёт свой ход
температуры воды; подбирается та глубина, при которой модельный ход совпадает со
спутниковым. Глубокий водоём инерционен: летний пик сдвинут и срезан; мелкий
следует за воздухом. По фазовому сдвигу и амплитуде глубина определяется
устойчиво даже при смещённых абсолютных значениях.

Скрипт сообщает, насколько острый получился минимум. Пологий минимум означает,
что глубина определяется плохо.

> Восстанавливается **эффективная термическая глубина** — характеристика
> теплового отклика, а не батиметрическая средняя. Подставлять её в расчёт
> объёма водоёма нельзя.

## Разработка

```bash
pytest tests/ -v                                  # 59 тестов Python
cd web && node test.mjs                           # расчётное ядро в браузере
PYTHONPATH=src python scripts/check_js_port.py    # JS против Python
```

`web/js/physics.js` — ручной порт `src/evap/physics.py`. Расхождение констант
даёт правдоподобные, но неверные числа, поэтому обе реализации прогоняются на
одинаковых входах с допуском 1e-9. Это часть CI.

Локальный запуск веб-версии — обязательно через сервер, ES-модули не работают по
`file://`:

```bash
python -m http.server -d web 8000
```

## Известные ограничения

**Ячейка ERA5-Land 9 км ≈ 81 км².** Водоём меньше этого получает метеоданные
преимущественно с окружающей суши, где воздух суше и теплее, — испарение будет
завышено. Приложение предупреждает об этом. Свойство исходных данных, а не
способа их получения.

**Rl↓ не измеряется, а оценивается.** Open-Meteo не отдаёт нисходящее
длинноволновое излучение; формула Брунта даёт около 10 % точности.

**Глубина перемешанного слоя параметризована грубо.** Заглушка на основе баланса
ветровой энергии и плавучести. Для рабочей системы заменить 1D-моделью
(Simstrat, GLM, FLake), калиброванной по спутниковой LSWT.

**Ледовый режим определяется по температуре.** Для точных дат нужен Sentinel-1 —
радар не зависит от облачности.

**Skin effect.** Дневные спутниковые измерения фиксируют температуру тонкой
поверхностной плёнки, которая может быть на 0.5–2 K теплее перемешанного слоя.
Ночные измерения MODIS этим не страдают.
